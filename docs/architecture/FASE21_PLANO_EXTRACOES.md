## Contrato do dispatcher composto

1. Preservar `http.createServer`, `requestContext`, tratamento de erros, telemetria, `OPTIONS`, health, rate limit e update desktop na ordem observada. Um request recebe contexto e rate limit **uma única vez**. A rota pode ser `GET` e ainda executar conciliação ou gravação de token; não inferir transação pelo verbo.
2. Preservar a seleção do wrapper (`repositoryMutationRoute`, exceções self-managed, `context.adminMutationLocked`, `req.commitResponseAfterMutation`) **antes** de delegar. Inicialmente manter a recursão existente de `handleApi` para não deslocar o commit; uma futura substituição por executor explícito exige teste separado de resposta diferida, rollback e nested route. O contexto `db` deve ser adquirido na mesma posição da sequência de guards até se provar equivalência.
3. Usar uma sequência explícita de **slots ordenados por posição original**, não um roteador que agrupa por prefixo. Cada factory recebe `{ req, res, pathname, method, db, actor, readDb, writeDb, withCriticalMutation, sendJson, ...capacidades de domínio }` de forma restrita e retorna `false` se não casa ou `true` se já respondeu/assumiu a resposta. Uma Promise rejeitada segue para o mesmo `publicApiError`. Não duplicar autorização em dezenas de handlers nem importar `server.js` de um módulo filho. Registrar o matcher antes da invocação, inclusive ordem dos handlers delegados já existentes.
4. Separar slots **pré-Admin** (tokens Studio/e-mail, catálogo comercial, login/2FA/logout/me e métrica de anúncio), o portão `ensureAdmin`, e slots **pós-Admin** na mesma ordem do [inventário](FASE21_INVENTARIO_ROTAS.md). `ensureAdmin` continua autoridade de sessão, 2FA, permissão e origem; ações internas (`orders.refund`, `box_office.courtesy`, owner de integrações) continuam antes da mutação ou efeito externo. Um handler não deve antecipar o fallback 404 de outro.
5. Manter serviços e repositórios existentes como donos de regra/estado: `movieCatalogHandler`, `venueConfigurationHandler`, `commercialCatalogHandler`, `catalogReadHandler`, `adminOverviewHandler`, `adminCustomerHandler`, `adminLogsHandler`, `cinemaSettingsHandler`, `pointCreationCoordinator`, `pointPaymentRecoveryHandler`, `ticketRefundCoordinator` etc. Não criar outro `handleApi.js` monolítico, nem duplicar cálculo de preço/estado financeiro. Submódulos de rotas devem ser coesos, tipicamente **200–600 linhas**, com revisão obrigatória a partir de 800 e justificativa acima de 1.200.
6. Instanciar serviços que têm provedor, timer, listener, worker ou conexão **somente** na composição/startup autorizado; import e modo quiescent não podem iniciar efeitos. Expor `close()`/`stop()` quando o recurso possui ciclo de vida. Identidade, URLs, credenciais e marca vêm da configuração da instalação, nunca de constantes do Cine Cruzeiro em módulo compartilhado.

### Slots de precedência que não podem ser fundidos livremente

`health → rate limit → desktop update → seleção transacional → origem cliente → readDb → token email → email automation → token Studio → Studio automation → catálogo comercial → login Admin → métrica pública → ensureAdmin → conta/2FA Admin → conteúdo/assentos → dashboard → Social Studio → relatórios → vendas de bomboniere/logs → pagamentos/integrações → e-mail Admin → cliente/auth/OAuth → Clube → catálogo/usuários/cupom → Pix/cartão → ingressos/Wallet → bilheteria/Point → validação → PagBank → Mercado Pago → pedidos → 410 legado → 404`.

A sequência sintetiza as 202 instruções; ações específicas, inclusive `handleTmdbSearchRoute` antes de Clube e `handleTmdbMovieRoute` depois, são fixadas na tabela gerada do inventário. O registro deve suportar slots intercalados do mesmo domínio. Não transformar pré-checagem de token ou permissão em pré-match de prefixo que bloqueia uma rota pública anterior.
